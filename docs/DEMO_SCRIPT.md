# Three-minute demo

| Time | Show | Explain |
| --- | --- | --- |
| 0:00–0:25 | Two QA identities in a private or group conversation | A client reports a broken login. Reload and find the same message. |
| 0:25–0:55 | Open the message action in the issue room. Choose Create issue. | Keep the original excerpt, pick the affected colleague and assign the resolver. Confirm and inspect the source link. |
| 0:55–1:30 | Start the work, complete the retest task and attach evidence. | Name what was tested and what remains uncertain. ProofGuard can review the descriptions with consent. |
| 1:30–2:10 | Request verification and show the resolver's review panel. | The resolver must wait for an independent reviewer. The same rule is enforced by the database. |
| 2:10–2:45 | Switch to the reviewer. Review evidence and approve or reject. | Each decision belongs to one specific request. Rejection and resubmission preserve history. |
| 2:45–3:00 | Find the verified issue in the command center and revisit the source room. | The client can trace what happened to the original report. |

The recorded acceptance run used real SDK messages and authenticated database actions. Label transitions driven by test automation. Use only QA identities in public footage.
